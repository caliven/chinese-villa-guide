## 户型编辑约束与制图口径（2026-10-19）

墙体拖动、方向键、长度输入和靠墙对齐共用 `wall-constraints.ts`：从操作开始的完整快照求解，保持正交及原有 L／T 接点；真实接点采用墙厚与 1 mm 数值容差，不把鼠标磁吸距离当作连接。墙长不足以容纳原门窗时拒绝编辑，保留洞宽及墙端方向。房间宽深输入和拉角共用事务，贯通共墙两侧及同侧相邻房间一起更新；出界、约束矛盾或挤出不足 800 的剩余房间时整次取消。800 是现有编辑器的几何下限，不是建筑规范对各类房间的统一最小尺寸。

右上角生成、画墙和改墙后的同步共用 `room-sync.ts`。四面围合（含外墙、实体墙与虚拟分界）自动生成闭合房间；新画墙或点击「自动生成房间」时，空置三面 U 形也可生成并标为“开敞分区”，不补画第四面墙。已有房间不重复生成，完整占用的挑空／楼梯区静默跳过；部分跨入保护区的候选仍拒绝，并显示分区宽深、距西／北墙位置和冲突对象。成功数量与待处理提示合并显示。自动开敞区同样关联稳定墙 ID，调整原墙会同步尺寸；补齐第四边后沿用原房间身份。普通墙微移只同步已有开敞区，不顺带新增开敞区。已有房间与稳定墙 ID 关联，重复生成保持幂等；删除边界墙后保留房间并标记“失围合”。楼梯与挑空通过专用模型调整，普通墙编辑不能暗中改变其三层洞口。楼梯不自带墙厚，也不作为共墙房间联动：自画侧墙可独立拖动、微移、改长或靠墙对齐，保留楼梯框和洞口参数；挑空边墙仍受保护。房间放置、平移、扩展及边界重算按完整轮廓检查保护区；新增覆盖时回滚，历史梯下卫等套叠仅允许维持或减少交集。数值编辑被拒绝时，输入框恢复实际尺寸。

L 形等正交凹形房间保存实际轮廓，填色、点选、标签位置和面积采用同一轮廓；宽深仅是外包络，不能用两数替代分段尺寸。净空按实体墙带并集扣减，交叉墙厚只扣一次；凹形房间须逐段改墙，暂不提供包络拉角和包络家具居中。含内院等有孔分区暂不自动生成，保留用户原房间。手工旧矩形继续显示原参考口径；建立墙边界关联后采用真实墙带净空。所有面积均为模型“墙线面积／净空面积”，未扣装修，不作为报建建筑面积或产权面积。

2026-10-20 内部分房修复：已有卧室等普通房间被真实墙线完整分割时，`room-subdivision.ts` 按全部闭合子区的实际轮廓核对铺满、重叠及保护区。最大未占用子区沿用原房 ID、名称和用途，保留 L 形凹口，其余子区新建为用途待确认的房间；已有明确匹配的内卫等子房优先沿用自身身份。旧稿小数毫米与墙线统一按坐标取整比较。画墙完成、移动墙完成、全局生成及手动放置共用该分割事务，手动入口仅处理点击区所在原房，并采用所选用途；一次操作可整体撤销。真实接墙判断由闭合检测及 U 形候选共用，端点接到外墙内皮／内墙墙皮即可识别，允许 1 mm 舍入缝，2 mm 及以上真实间隙不代补。分割冲突或带孔残余会保留原稿并提示原因，手动放置和吸附撑满不再在已有普通房间上重复填色。

图面表达参照[《房屋建筑制图统一标准》GB/T 50001-2017](https://ebook.chinabuilding.com.cn/zbooklib/book/detail/show?SiteID=1&bookID=102879)与[《建筑制图标准》GB/T 50104-2010](https://ebook.chinabuilding.com.cn/zbooklib/book/detail/show?SiteID=1&bookID=57783)。上述约束求解与房间关联是本项目实现选择，标准并未规定软件必须采用哪一种算法。房间围合、失围合和重复占区的处理也参考[建筑软件的房间边界机制](https://help.autodesk.com/cloudhelp/2025/ENU/Revit-ArchDesign/files/GUID-65668F88-4429-4992-AA0D-1C4FBDCFA650.htm)。本轮不构成完整施工图、结构或消防审查。

源码默认二层公卫原房间框越南墙 600，现收为 2400 进深并把马桶放回墙内净空；已保存的户型 JSON 不自动重写。

## 编辑性能与加载反馈（2026-10-19）

二维编辑只暂存草稿并标记三维待更新；进入「立体剖看」、场地模型或日照视图时，集中应用最新草稿。同内容重复暂存不重复构建。普通户型修改由 `Viewer.rebuildLayout` 仅更新变化楼层／辅楼，保留场地、道路、邻房、路线及未变化的屋顶、门厅；楼梯和挑空会使相关楼板、梯段重新生成。外轮廓及场地参数变更仍走完整重建，不用局部缓存跳过几何联动。

指针移动、选择与提交按帧合并重绘，更新变化的 DOM 属性／文字，保留 SVG 根节点及编辑事件绑定。房间填色、标签、包络与净空面积复用同一计算结果；缓存指纹包含原地修改的墙线、墙厚、房间轮廓及建筑包络，不改变既有尺寸和面积口径。

场景初载、立体更新、户型版本载入与实景查看器的加载反馈统一使用 `shared/loading.css`。`loading-overlay.ts` 先让遮罩绘制再执行同步重任务，结果帧呈现后关闭；重叠任务全部结束才关闭，失败也会清理遮罩并保留待同步草稿。已同步的相同内容重复切换不重复构建。外墙门窗和门厅草稿现也传入三维；若改动正立面通高洞口，采用逐层实际门窗表达，取消原位置的专用通高玻璃装饰，默认未改的立面保留原细节。

本轮类型检查与 297 项测试通过，两套查看器构建成功。Chrome 桌面 1728×901、手机视口 390×844 检查编辑入口、载入233620、尺寸联动、超限回显、拖墙、方向键、撤销、平面／立体切换及遮罩，未见应用控制台错误或警告。慢速遮罩验证临时使用8倍CPU减速，结束已恢复。浏览器单次编辑入口观测：主线程任务增量约37 ms、脚本约8 ms（包含测试工具开销，非输入延迟或跨设备承诺）。Node 别墅构造＋合批分段：全量约1156 ms，单层家具局部更新约28～35 ms；不含场地、DOM及GPU。构建仍提示单包超过500 kB，未在本轮拆分依赖。

## 分层户型编辑（2026-10-16）

属性浮窗可按住房间、墙体、家具等面板的标题栏拖动；输入框和删除按钮保持原交互。初次选中时自动贴近模型，手动拖动后，本次页面会话内切换对象、修改属性、滚动或缩放图纸均保留位置，并限制在编辑区内、避开顶部工具条；较长面板可内部滚动。刷新页面后恢复自动定位，浮窗位置不写入户型数据。

打开「分层户型 → 平面图 → 编辑布局」。可调主楼房间、隔墙门洞、家具、楼梯与门厅位置；外墙锁定。墙体工具含隔墙／承重／**虚拟墙**：虚拟墙为细灰虚线分界（无厚度、不进立体），用于打通区域仍看清分区标线与宽深；两端接墙围合后显示分区尺寸。**四面墙（含虚拟）围合后自动生成房间；三面相接墙线形成的空置 U 形可生成开敞分区**，色块贴墙内皮充满该区；属性显示套内／建筑面积示意；房内家具随房间整体移动，房间始终画在家具下方。草稿随方案一并保存在 `public/scheme/`；「导出定稿 JSON」后放到 `references/layout-draft.json`，再让助手回写 `data.ts` 并构建。二维编辑期间不自动重建三维；切换立体时应用最新草稿。

平面图标签在「一层」前有「院坪」总图：自家主辅楼与门厅只画外轮廓，前院按当前圆弧标出墙角／门厅／屋后到外沿的余量；邻居按口述面宽13000、进深10800（8800＋2000），水泥外院坪与东界外沿齐平。院坪页不可编辑布局。

尺寸版本存 `data/尺寸/`，户型版本存 `data/户型/`（三层及辅楼一体）。打开页面默认载入户型目录第一项，切换视图保留当前编辑。「新增」保留建筑外壳、层高和外部门窗，清空内部房间／墙／家具、楼梯及挑空；「复制」保存当前完整布局（含未保存编辑）到独立版本；「重命名」只改已保存版本名称，保留文件编号、排序、时间和图纸内容。保存当前版本、新增、复制均置顶；同秒连续创建自动避开编号冲突。现仅保留233620（二三层确认草案）和200459两份原版本，三个旧版本已按用户要求移除。当前工作稿仍可「保存到文件」写 `public/scheme/current.json`。「恢复默认」只还原源码默认值。开发时 `npm run dev` 经 `/__data_save` 直写；静态页下载 JSON，并在本次页面会话内保留版本，刷新前需将文件和目录索引保存到源数据。静态服务本身不能写仓库。构建将 `data/` 复制到 `villa-3d/data/`。

### 户型尺寸引用（2026-10-18）

一层主楼与辅楼分成两张独立图纸，桌面并排、手机上下排列，各自标注四侧墙线定位及总宽／总进深；二三层只画主楼。图间留白不是实际子孙道，两栋楼仍共用场地坐标、尺寸参数和一份三层户型草稿。图上「统一尺寸 · 两图联动」可展开查看21000面宽分配、后墙齐平与辅楼内退关系；外轮廓与子孙道仍在「尺寸设置」统一调整，西侧间距和内退自动重算，超宽或辅楼进深超过主楼时禁止应用。

进深还按院坪弧线在各楼实际面宽范围内检查：主楼／辅楼均计入屋后预留，门厅另加外伸；改面宽、子孙道、进深或院坪尺寸都会重算，不能借用东侧最深处作为全场进深。此为当前概念几何的包络校验，非界址或施工验收。

外圈总尺寸、主辅楼外皮、两侧余量及子孙道只取建筑参数；主楼门头侧（北侧；旋转后在画面下方）另标门厅柱心**控制尺寸**（默认左余4500＋柱心距4600＋右余4500），不代表已确定的结构轴网。房间色块、楼梯间框及套内空间不参与该控制分档。楼梯框不投外圈墙线尺寸，避免框边与自画侧墙之间出现18等碎档；梯间宽深在模型内标注。与四周外墙相交的**实体**内墙另加靠近建筑的一档**墙线定位**（接哪侧外墙就只标哪侧；贯通墙不对边重复）；虚拟分界不投外圈。总宽只标门头侧（北）、总进深只标东侧，避免对边重复。短墙、拆段墙同样按实际相接关系判断，悬空内墙不投影。房间框尺寸与模型内侧参考另列，不能混为净尺寸。

`src/plan-dimensions.ts` 统一尺寸引用，端点先统一到毫米再相减，所有分段之和须等于总长；真实短段不按墙厚吞并。尺寸引出线回到对应主／辅楼墙面。参照建筑软件对[墙面、墙中线和定位线的区分](https://help.autodesk.com/cloudhelp/2023/ENU/Revit-ArchDesign/files/GUID-F26DB6DA-A0EC-424D-B656-3BDF47607F4F.htm)，当前实现只对模型正交墙定位，不代替施工图。

房间吸附采用同栋建筑外皮与内墙参考，不再吸到外墙中线；松手遵守吸附开关和 Shift，且不再跨数米寻找远墙。仅点选不改几何，拖回原点时独占墙与家具也须回到拖前位置。既有保存稿中的房间、墙体位置不会被自动改写。

### 楼梯分层表达（2026-10-18）

南北向楼梯默认图左（东侧）起步。一层画起步梯段和平台，图右返跑用上方投影虚线表示，梯下留空，可放置、选中和拖动家具；不再用整块房间底色或落地实心楔块占满梯下。二三层画两跑实际踏步；楼梯模型不自带侧墙（墙体用「隔墙」工具自画），踏步按已有墙内侧取净空。三楼仅标下行；单层立体剖看也显示从下层上来的楼梯。二楼挑空南缘默认实体墙；临空边栏杆用家具「栏杆」自画，不再写死 L 形虚线。

`src/stair-geometry.ts` 统一平面、立体、楼板洞口和板底净高；梯段宽、踏步深、踢面数、平台、方向均读取当前草稿，不再混用默认值。洞口及梯间至少包住两跑和平台。编辑属性可切换起步侧，旧 JSON 缺省沿用上述方向，新值可保存／载入。净高按实际踏板和平台示意，不把梯井缝或预留区当作平台封顶；实际家具高度与梁板净高仍需现场和结构图核对。

梯间框只作模型定位，不视为墙线，不额外占用墙体厚度。外圈尺寸仅取真实墙线，移动／拉宽楼梯不会添加或拆分外圈尺寸档；自画侧墙移动后按其真实位置更新墙距。梯间范围跨出主体时显示提示，不自动移动或覆盖用户保存稿。

## 坐标与设计约束

**长度全部为毫米（mm，整数；图纸与界面数字不带单位后缀）；面积仍为 ㎡。** Three.js 渲染仍用米：`viewer.ts` 的 `mmRoot` 根节点 `scale = 0.001`，方案／场地／路线几何都以 mm 建模，相机与世界坐标为米；换算见 `src/units.ts`（`toM`、`areaM2`、`formatMm`）。旧米制 JSON（`mainWidth<100`、层高<100）载入时自动迁成 mm。下文若仍见“米”叙述，按 ×1000 读作 mm，以 `DEFAULT_VILLA_PARAMS` 与「当前真相」为准。

## 必须保留的未决项

1. **车辆通行尚未通过校核。** 用户提供入口预估2.5米净宽、邻居平台拟切开为露天口的意向；实际切口范围与协商结果仍待确认。道路位置已校正到面对房子时邻居木房的左侧。场地视图前地坪完整，地库视图用投影提示保留地坪、用虚线标拟切口；接入仍经过保留地坪下方，净高待测。模型5×2.5米切口形状不是协商结果。L9长5.218米、车身宽1.998米、高1.8米、轴距3.105米；车宽不含镜。第二辆星愿只作外观，不参与L9占位检查。当前空间探索曲线已补整车平面扫掠和模型柱墙投影潜在冲突筛查，但不是按转弯半径生成的轨迹；后视镜、坡道纵向扫掠、实际净高、驶出或第二辆独立进出仍未完成校核。
2. **标高与结构待测。** 道路初值沿用 `surroundings.road.entryY` 的连续纵坡示意值，坡长初值5米；两者都待测、可探索调整。院坪结构暂占0.45米，地库地面-2.95米，从而表达梁下2.5米净高目标；不能由此认定开挖深度或结构梁高可行。邻居梁底1.8米/板底2米没有用于推算道路标高。
3. **双桌满座通道偏紧。** 32㎡辅楼（默认进深 8 m、面宽 4 m）摆入直径2米的12座圆桌及6座小桌，实体座椅在墙内；完全拉椅时圆桌东侧余量更紧，两桌包络可能局部相交。页面直接显示这一问题，不将“摆得下”当作“同时满座通行合格”。仍需在10/12人、桌径、座椅形式及辅楼功能分配之间深化。
4. **日照是模型比较。** SunCalc 2.x使用北起顺时针的角度，统一北京时间。窗外3点每半小时射线采样表示直射遮挡，不能折算为室内照度或法定日照时数。树叶透明贴图在射线中按叶簇面片概括，近似树形、地形和邻房均影响结果。
5. **不是施工图。** 梁柱、砖混承重体系、挑空开口、楼梯细部、地库承托、邻居平台切割、挡土排水与柴火烟道需结合现场完成专业设计。模型不认定土地界址或审批范围。
